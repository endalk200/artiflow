MDX becomes especially useful when prose needs a small amount of interaction. Components are registered once in `components/mdx.tsx`, then used by name from any content file.

## Steps

<Steps>
  <Step>
    ### Register

    Add the React component to the MDX component map.
  </Step>
  <Step>
    ### Author

    Use the component by name in an `.mdx` file.
  </Step>
  <Step>
    ### Interact

    Client components keep their state and event handlers.
  </Step>
</Steps>

## Accordions

<Accordions type="single">
  <Accordion title="Can an MDX file import its own component?">
    Yes. A shared component map is simply more convenient when the same primitives appear on many pages.
  </Accordion>
  <Accordion title="Can the component use React state?">
    Yes. Mark the component module with `use client`, just as you would elsewhere in a Next.js App Router project.
  </Accordion>
  <Accordion title="Is the surrounding page still server-rendered?">
    Yes. A client component can be an interactive island inside the otherwise server-rendered MDX page.
  </Accordion>
</Accordions>
