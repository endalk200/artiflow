MDX keeps ordinary Markdown pleasantly ordinary. The interesting part is that each element can be replaced by a React component at render time.

## Text and emphasis

Use **strong text**, *emphasis*, ~~strikethrough~~, `inline code`, and [links](https://mdxjs.com/) in the same paragraph. Footnote-like context can often be expressed more clearly with a callout:

<Callout type="warn" title="Markdown inside JSX">
  Leave a blank line around block Markdown nested inside JSX components. It keeps the MDX parser—and future readers—happy.
</Callout>

## Lists and tasks

- Plain Markdown remains portable.
- MDX adds JSX expressions and components.

## Expressions

MDX can evaluate safe build-time expressions directly in content:

<div className="not-prose my-6 grid grid-cols-3 gap-3">
  {['Author', 'Compile', 'Render'].map((label, index) => (
    <div key={label} className="rounded-xl border border-fd-border bg-fd-card p-4 text-center shadow-sm">
      <span className="text-xs text-fd-muted-foreground">0{index + 1}</span>
      <p className="mt-1 text-sm font-medium">{label}</p>
    </div>
  ))}
</div>

That row is generated from an array expression written directly in this MDX file.
