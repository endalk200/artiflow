# Make Creation and Publication Idempotent

Project creation and Artifact publication accept a client-generated idempotency key that the CLI reuses across automatic retries, storing that key with the resulting Project or Revision so a repeated request returns the original response instead of creating duplicate records. Publication hashes cover the target identity, Source Format, source, and—when appending—the expected current Revision ID. Reusing a key with different request content returns a conflict. PostgreSQL transactions take a transaction-scoped advisory lock derived from the idempotency key before checking or writing it, so concurrent identical requests replay instead of leaking a unique-index failure. Revision-conflict responses are never automatically retried as new writes; the idempotency fields are infrastructure metadata and do not add another domain entity.
